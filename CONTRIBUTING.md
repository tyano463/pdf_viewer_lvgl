# Contribution Guidelines

Thank you for your interest in contributing to this project!  
All kinds of contributions are welcome—bug reports, feature suggestions, documentation improvements, and code enhancements.

Please follow the guidelines below to help us maintain a high-quality project.

---

## 🔍 Before You Start

- Check the [Issues](./issues) to see if your idea or problem has already been reported or discussed.
- If you are planning a significant change, please open an issue first to discuss it before submitting a pull request.

---

## 🐞 Reporting Bugs

When reporting a bug, please include the following details:

- Steps to reproduce the issue
- Expected behavior vs. actual behavior
- Operating system and toolchain version
- Relevant logs, screenshots, or stack traces if available

---

## 💡 Suggesting Features or Improvements

To suggest a new feature or improvement, please describe:

- What the feature does
- Why it would be useful
- Any references, links, or prior art (if applicable)

---

## 💻 Contributing Code

1. Fork the repository and create a new branch from `main`.
2. Write clear, maintainable C code.
3. Add or update tests if applicable.
4. Run existing tests to ensure nothing is broken.
5. Submit a pull request with a clear description of your changes.

---

## 📐 Coding Style

- Use 4 spaces for indentation (no tabs)
- Use `snake_case` for function and variable names
- Keep comments brief and in English
- Avoid unnecessary macros; use inline functions where possible (if supported)
- Group related functions and declarations logically

(Please adapt to your project's specific coding standards if any.)

---

## 🙏 Thank You

We appreciate your contribution and will review your pull request as soon as possible.  
Together, we can build something great!
